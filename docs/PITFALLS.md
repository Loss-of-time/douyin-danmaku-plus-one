# 踩坑记录

每条按「现象 → 原因 → 做法」写。

## 1. 右侧聊天区没有 +1

- **现象**：画面上的弹幕有按钮，右侧消息列表里的消息没有。
- **原因**：需求只要画面弹幕。两者不是同一条渲染链：画面弹幕是 `CanvasDanmakuPlugin` 里的 canvas，右侧是 `webcast-chatroom___item` 的 DOM。
- **做法**：鼠标移到视频画面上飘过的文字上。右侧聊天区刻意不碰。

## 2. 未登录时点击只显示 ×

- **现象**：悬停正常出按钮，点下去变 `×`，没有发送。
- **原因**：抖音对未登录用户不渲染聊天输入框，`#chatInput` 不存在，脚本拿不到编辑器。
- **做法**：登录后再用。这不是脚本能绕过的。

## 3. 按钮会跟着弹幕移动，鼠标要追一下

- **现象**：鼠标停在一条弹幕上，`+1` 按钮会随着弹幕往左走，不会把弹幕停住。
- **原因**：这是按“不暂停弹幕”做的：主线程每帧收到新坐标就挪按钮。鼠标移到按钮上后，按钮会停住不再跟，弹幕继续走，方便点击。
- **做法**：直接朝按钮移过去，碰到按钮后它就不动了；点完或移开就消失。

## 4. 同一行有两条相同文字时可能跟错

- **现象**：悬停“？”、“哈哈”这类高频短句时，按钮跟到了旁边另一条同文本弹幕上。
- **原因**：worker 的 `fillText` 只给文字、坐标和字体，没有弹幕 ID。脚本按“文字相同 + 同一行 + x 在 120px 容差内”找下一帧的位置，靠得特别近的同文本会撞上。
- **做法**：已知取舍。移开再重新悬停；不要为了这个引入更重的 canvas 重绘方案。

## 5. ✓/× 只是输入框状态，不是服务端回执

- **现象**：右侧聊天区已经出现自己发的弹幕，按钮却短暂显示 `×`；反过来，按钮显示 `✓` 也不保证平台已经收下。
- **原因**：脚本没有发送接口的返回值，只能看输入框是否在 600ms 内清空。弱网、审核拦截、服务端慢都会让这个推断失真。
- **做法**：先看右侧聊天区确认是否已发出，不要连点；连点会被脚本的 `sending` 锁挡住，但平台仍可能判频繁。真要改，应在发送后监听聊天区新增消息，而不是加长等待。

## 6. 抖音改版后整段失效

- **现象**：`+1` 完全不出现，或控制台里 `window.Blob.__dy1Patched` 为 `undefined`。
- **原因**：脚本依赖两个内部实现：播放器用单段 `importScripts(` 的 Blob 建 worker，以及弹幕画在 `OffscreenCanvasRenderingContext2D` 上。任一改变都会断。
- **做法**：先用 WORKFLOW 里的命令确认 canvas 和 Blob 补丁；再对照新版播放器 bundle 找新的 worker 创建方式/绘制上下文，更新 `hookWorker` 的过滤条件和 `WORKER_PATCH` 的 hook 点。

## 7. 全屏下没有按钮

- **现象**：普通窗口正常，进全屏后悬停不出 `+1`。
- **原因**：按钮挂在 `body`；全屏元素进入浏览器顶层（top layer），`body` 里其它固定定位元素不会画在全屏内容上。
- **做法**：先退出全屏。要支持全屏，得在 `fullscreenchange` 时把按钮挪进全屏容器；当前版本没做。

## 8. 点 +1 会把输入框里的草稿顶掉

- **现象**：聊天框里已经打了一半的字，点 `+1` 后没了，变成要复读的那条弹幕。
- **原因**：发送前会全选输入框内容再插入目标文字；这是为了让编辑器状态和显示内容一致，否则发送键可能不启用。
- **做法**：先把草稿发出去或清空再点 `+1`。脚本不备份草稿；发送失败时留在框里的是复读内容，不是原草稿。
